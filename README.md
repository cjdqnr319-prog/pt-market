# 🎛️ 평택 물류 관제실 「오늘의 물류 시장」

중3 수송기술 4차시 · **공용 주문 시장 + 실시간 운영 타이쿤** (45분)

전자칠판에 평택 물류 시장판이 떠 있고, 하루(06:00→24:00 = 실제 6분) 동안 주문이 시간대별로 올라옵니다.
6개 물류회사(모둠)는 태블릿에서 **선착순으로 주문을 수락**하고 자사 트럭(합적·왕복 재사용)·철도/선박/항공 위탁·보관·포기로 배차합니다.

## 1. 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 시작 화면 (교사 / 모둠 / 로컬 테스트 / 오프라인 1인 모드) |
| `teacher.html` | **전자칠판 시장판** — 방 코드·QR, 게임 시계, 주문 시장 그리드, 평택 중심 지도, 돌발 팝업, 리더보드, 정산쇼, 최종 결산, 교사 제어바 |
| `student.html` | **모둠 태블릿 관제실** — 입장(PIN), 자원 게이지, 시장 미니 뷰·수락·VIP 입찰, 배차판(트럭 적재·출발 / 위탁 / 보관 / 포기), 운송 현황, 성적표·한 줄 회고 |
| `engine.js` | 시계·견적·배차·판정·정산 계산(순수 함수) + 호스트 루프(돌발 발동, VIP 판정, 폐장) |
| `market-data.js` | 목적지·수단 규칙·라운드별 주문(`t_in`)·돌발 덱·별점 규칙 |
| `realtime.js` | 실시간 동기화 계층 (Firebase RTDB / 로컬 / 1인 모드 공통 API, 트랜잭션) |
| `ui.js` · `common.css` | 공통 UI(효과음·토스트·모달·지도) · 다크 관제실 스타일 |
| `firebase-config.js` | **Firebase 설정을 붙여 넣는 곳** |
| `market_rounds.json` | 첨부 원본 데이터 (라운드별 주문 풀·유입 시각·최선 수단 참고) |

> 모든 진행 상황은 DB에 저장된 "기록"(수락·배차·포기·보관·돌발)에서 매번 다시 계산됩니다. 태블릿을 새로고침·재접속해도 상태가 어긋나지 않습니다.
> 엔진은 `market_rounds.json`의 R1~R3 주문 100건의 `best`·`best_profit`을 **100% 똑같이 재현**합니다(비용·시간 모델 검증 완료).

## 2. 설치 (Firebase — 여러 태블릿에서 함께 하기)

1. [Firebase 콘솔](https://console.firebase.google.com) → 프로젝트 만들기 → **Realtime Database** 만들기
2. 프로젝트 설정 → 내 앱 → 웹 앱 추가 → `firebaseConfig` 복사
3. `firebase-config.js`의 `window.FIREBASE_CONFIG = null;` 을 복사한 객체로 교체 (**`databaseURL` 필수**)
4. Realtime Database → 규칙(수업용 최소 규칙):

```json
{
  "rules": {
    "rooms": {
      "$code": { ".read": true, ".write": true }
    }
  }
}
```

5. 폴더 전체를 웹에 올리기 (GitHub Pages / Firebase Hosting / Netlify 등 아무 정적 호스팅)
   - 전자칠판: `teacher.html` → 방 코드와 QR이 뜸
   - 태블릿: QR 스캔 또는 `student.html` 접속 → 방 코드 입력 → 모둠 선택 → 회사 이름·PIN

`firebase-config.js`가 비어 있으면 자동으로 **로컬 모드**(같은 브라우저 탭끼리만 동기화)로 동작합니다.

## 4. 규칙 요약 (engine.js 구현 기준)

### 시간
- 게임 1시간 = 20초 (튜토리얼 10초). 06:00 개장 · **22:00 이후 출발 불가** · 24:00 폐장·정산
- 폐장까지 출발 못 한 수락 주문은 **자동 포기** 처리 (위약 30%, ★−1)
- 24시 이후 도착하는 장거리 화물(선박 등)도 도착 시각 기준으로 정산

### 자원 (라운드마다 리셋)
- 🚚 트럭 **일반2 + 냉장1** · 적재 ≤10톤 · **같은 목적지 합적** · 왕복 후 재사용 (냉장 트럭은 일반 화물도 실을 수 있음)
- 👷 인력 R1 6 / R2 6 / R3 7 — 수락 시 1명 **예약**, 배차 1편 = 1명(선박 2명). 합적하면 예약이 1명으로 합쳐져 인력이 남음
- 💵 예산 R1 800 / R2 900 / R3 1000 — 당일 지출(운임·보관료) 한도
- 📥 동시 처리 한도 4건 (수락했지만 아직 출발 안 한 주문)

### 수단
| 수단 | 시간 | 비용 | 조건 |
|---|---|---|---|
| 🚚 자사 트럭 | 거리÷60 + 0.5h (폭설 ÷40), 복귀 = 거리÷속도 | 거리×0.5 + 15 (1편당) | ≤10톤, 위험물 ✗, 냉장 화물은 냉장 트럭 |
| 🚆 철도 | 거리÷80 + 2h | 거리×0.6×무게계수 + 30 (+냉장 10) | 18:00 막차 |
| 🚢 선박 | 거리÷30 + 3h | 거리×0.25×무게계수 + 50 (+냉장 10) | 항만 목적지, 인력 2 |
| ✈️ 항공 | 3.5h + 거리÷600 | 거리×1.2×무게계수 + 70 | ≤3톤, 위험물 ✗, 폭설 결항 |
| 📦 보관(이월) | — | 20 | 마감이 내일(24시 초과)인 주문만 · 다음 라운드 06:00에 같은 회사로 이월, 마감 −24h (R0·R3 불가) |
| ❌ 포기 | — | 배송료 30% 위약 + ★−1 | 포기한 주문은 ⚡긴급 재수배 대상 |

무게계수: 철도 <10톤 1 / 10~100 2 / ≥100 3 · 선박 <100 1 / ≥100 1.5 · 항공 <1톤 1 / 1~3톤 2

### 수락 버튼 활성 조건
진행 중 · 22시 전 · 처리 한도 미달 · 인력 ≥1 · 예산 여유 · **지금 쓸 수 있는 수단 존재**
(트럭은 맞는 트럭이 지금 대기 중이어야 함 — 예: 냉장 트럭이 나가 있고 철도도 막차가 지났으면 냉장 화물 수락 불가, 이유 표시)
수락은 서버 **트랜잭션**으로 처리되어 동시에 눌러도 1개 모둠만 성공합니다.

### ⭐ VIP 역경매
- 등장 후 **실시간 10초** 동안 각 모둠이 배송료 이하 가격을 입찰(수정 가능)
- **최저가 낙찰**, 동점은 별점 높은 쪽 → 그다음 먼저 입찰한 쪽. 낙찰가가 그 모둠의 배송료
- 판정 시 처리 한도·인력이 안 되면 다음 입찰자에게. 입찰이 없으면 유찰
- 태블릿의 `💡 원가 견적 보기`로 수단별 원가를 확인 가능

### 고객 별점 (R1~R3 누적, 시작 ★3.0)
정시 +0.1 · VIP 정시 +0.3 · 지연 −0.3 (+위약 배송료 10%/시간, 올림) · 포기 −1.0
→ 다음 라운드 배송료 배수: ★4.0+ ×1.1 / ★3.0+ ×1.0 / ★2.0+ ×0.9 / 그 이하 ×0.8

### ⚡ 돌발 (라운드당 2개 · 시각 고정 · 내용은 덱에서 랜덤, 같은 라운드 중복 없음)
| 팝업 | 효과 |
|---|---|
| 🔧 트럭 고장 | 랜덤 2~3모둠의 트럭 1대 1시간 정지 (운행 중이면 도착·복귀 +1h, 대기 중이면 1시간 출발 불가) |
| 🚧 도로 통제 | 특정 목적지 트럭 도착 +1h (2시간 동안 출발하는 편) |
| 🚆 철도 임시 증편 | 1시간 동안 철도 비용 −30% |
| 📞 취소 전화 | 시장의 미수락 주문 2건 소멸 |
| ⚡ 긴급 재수배 | 포기된 주문이 배송료 1.5배로 시장 재등장 (포기 주문이 없으면 다른 돌발로 대체) |

돌발 시각: R1 10:00·14:30 / R2 09:30·13:30 / R3 10:00·15:00 (`market-data.js`의 `popupTimes`)

## 6. 데이터 모델 (Firebase `rooms/{code}`)

```
meta:   { game: "pt-market", created }
state:  { phase: lobby|ready|running|paused|settle|final, round, clockBase, anchorAt, speed, done:{R1:true} }
market/{round}/{orderId}: { ...order, status: open|taken|vip|expired|cancelled, owner, price, takenAt, bids:{g1:{price,at}}, vipWin }
popups/{round}/{key}:     { type, at, until, title, desc, targets|dest|oids|src }
groups/{g1..g6}: { name, pin, joinedAt,
  rd/{round}: { disp/{id}: {mode, truck, dest, oids[], depart, arrive, ret, cost, ppl},
                load/{n1|n2|c1}/{orderId}: true,       // 출발 전 트럭 적재 (되돌리기 가능)
                ord/{orderId}: {st: abandoned|stored, at},
                memo } }
```
- 게임 시계: 교사 화면이 `clockBase + (서버시각 − anchorAt)/초당` 을 기준으로 계산하고, 모든 기기는 Firebase 서버 시각 보정(`.info/serverTimeOffset`)으로 같은 시각을 봅니다.
- 호스트 작업(폐장·돌발·VIP 판정)은 교사 화면에서 트랜잭션으로 실행되어, 교사 화면을 두 개 띄워도 중복 실행되지 않습니다.

## 7. 밸런스 조정
`market-data.js`에서 트럭 편성(`FLEET_DEFAULT` 또는 라운드별 `fleet`, n=일반·c=냉장), 라운드별 `secPerHour`(속도), `ppl`, `budget`, `popupTimes`, 주문 목록, `STARS`, `ACTIVE_LIMIT` 등을 바꾸면 바로 반영됩니다.
